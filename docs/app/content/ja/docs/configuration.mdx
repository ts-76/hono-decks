# 設定ファイル

ビルド設定はhono-decks.config.ts、実行時の設定はcreateDecks()で管理します。

CLIのinitはビルド設定を `decks/config.ts`、実行時の設定を `decks/index.ts` にまとめ、設定の場所をpackage.jsonへ記録します。Viteのフレームワーク別initは `hono-decks.config.ts` とアプリ側の設定ファイルを維持します。既存の構成や設定パスの明示指定も引き続き使えます。

<section id={"files"}>

## 4つのファイルの役割を把握する

`hono-decks init`は`hono-decks.config.ts`、`src/decks.ts`、サンプルのデッキを作り、生成先を`.gitignore`に追加します。設定ファイルはビルド専用で、CLIとViteプラグインだけが読み込みます。Workerには含まれません。

{term: <><code>{"package.json"}</code></>, description: <>{"ViteまたはWranglerを使う、普段の開発コマンドを定義します。"}</>}]} />

Viteを使う場合(`init --framework hono`、`honox`、`void`)は、生成物をメモリ上に保持し、`src/decks.ts`は`virtual:hono-decks`から`createDecks`を読み込みます。`build.outDir`は不要です。

```ts
/// <reference types="hono-decks/vite-env" />
import { createDecks } from "virtual:hono-decks"

export const decks = createDecks()
```

<Callout title={"2つのファイルで役割を分けます"}>

コンパイラーは`build`を読み、`mountPath`を生成モジュールに埋め込みます。リクエストごとに動く設定はすべて`createDecks()`に渡します。

</Callout>

## コンパイラーを開発フローに組み込む

Viteでは`honoDecks()`を追加し、Wranglerではカスタムビルドに`hono-decks compile`を登録します。どちらも普段の`dev`コマンドがデッキをコンパイルするため、専用のスクリプトは不要です。

<section id={"runtime"}>

## リクエストごとに変わる値を設定する

実行時の設定は`createDecks()`に渡します。型引数を指定すると、HonoのBindingsとVariablesも各関数の型検査の対象になります。`dev`を省略した場合は、ViteとWranglerが設定する`NODE_ENV`から環境を判定します。標準設定では、`vite`と`wrangler dev`は開発モード、プロダクションビルドと`wrangler deploy`は本番モードとして動作します。boolean値または関数を明示すると自動判定より優先されます。環境を判定できない場合は、安全のため本番モードになります。

<CodeBlock filename={"TypeScript"} language={"typescript"} code={"// src/decks.ts\nimport { createDecks } from \"#decks\"\n\ntype AppEnv = {\n  Bindings: {\n    PRESENTER_ENABLED?: string\n  }\n  Variables: {\n    language: string\n  }\n}\n\nexport const decks = createDecks<AppEnv>({\n  document: {\n    lang: ({ c }) => c.get(\"language\"),\n  },\n  presenter: {\n    enabled: ({ c, dev }) => dev || c.env.PRESENTER_ENABLED === \"true\",\n  },\n})"} copyLabel={"コピー"} copiedLabel={"コピーしました"} errorLabel={"コピーできませんでした"} />

`c.get("language")`を使う例では、Honoの`languageDetector()`を先に登録します。手順は[HTMLとセキュリティ](/docs/security?lang=ja#language)で確認できます。多言語対応が不要なら`lang: "ja"`のように固定値を指定します。

</section>

<section id={"facade"}>

## 設定が上書きされる順序を確認する

設定は生成時の既定値、`createDecks()`に渡した設定、`decks.router(overrides)`の順に適用されます。結合の規則は1つです。オブジェクトは入れ子まで結合し、配列はつなげ、それ以外の値(`false`や関数を含む)は後の値で置き換えます。

<CodeBlock filename={"TypeScript"} language={"typescript"} code={"// src/index.ts\napp.route(\n  decks.mountPath,\n  decks.router({ viewer: { controls: { hidden: [\"print\"] } } }),\n)"} copyLabel={"コピー"} copiedLabel={"コピーしました"} errorLabel={"コピーできませんでした"} />

<Callout title={"公開パスは1か所で指定します"}>

`mountPath`は設定ファイルに一度だけ書き、実行時は`decks.mountPath`を使います。別のパスにルーターを登録すると、分かりやすいエラーになります。

</Callout>
