# 導入

パッケージを追加し、最初のデッキをHonoアプリで表示するまでの手順です。

1.xから更新する場合は、[2.0移行ガイド（日本語）](https://github.com/ts-76/hono-decks/blob/main/MIGRATION.md#日本語)を参照してください。設定の移動、API名の変更、削除された機能をまとめています。

<section id={"prerequisites"}>

## アプリを用意する

npm、pnpm、Yarn、Bunのいずれかと、起動できるHono、HonoX、またはVoidアプリが必要です。フレームワーク別の導入では、通常`/decks/welcome`にサンプルを表示します。汎用CLI・ファイル生成方式では`/decks/welcome`を使います。

<Callout title={"コンパイルと配信は分かれています"}>

MDXの変換はローカルの開発・ビルド環境で行います。Honoアプリは生成済みモジュールを読み込むため、Cloudflare Workers上でファイルシステムへアクセスする必要はありません。

</Callout>

</section>

<section id={"framework-init"}>

## アプリに合った導入方法を選ぶ

既存のHono + ViteまたはHonoXアプリでは、`hono-decks`を追加して対応するコマンドを選びます。VoidではVoid用コマンドを使います。`--install`は不足している互換性のあるMarkdown依存を、アプリのパッケージマネージャーで追加します。未対応の設定や既存の統合がある場合はCLIの案内を確認してください。

```sh
npm install hono-decks
# いずれか1つを選ぶ
npx hono-decks init --framework hono
npx hono-decks init --framework honox
npx hono-decks init --framework void --install
npm run dev
```

いずれの方法も既存のスクリプトを維持し、`virtual:hono-decks`を使用します。`dev`と`build`はメモリ内でデッキをコンパイルします。initが表示したサンプルのURL（通常は`/decks/welcome`）を開いてください。HonoとHonoXのサンプルはMDX、Voidのサンプルは操作できるIslandを含むMarkdownです。対応バージョン、任意の依存関係、設定上の制約は[パッケージのREADME](https://github.com/ts-76/hono-decks/blob/main/packages/decks/README.ja.md)を参照してください。

VoidでMDXを使う構成は、[Voidの実例](/docs/examples?lang=ja#void)で確認できます。この実例にはHono Markdownアダプターは必要ありません。

フレームワーク別の導入はここまでです。以下は手動統合やWrangler向けの**汎用CLI・ファイル生成方式**です。この方式の`init`は標準で`/decks`を使い、`compile`は生成ファイルをディスクに出力します。

</section>

<section id={"install"}>

## パッケージを追加し、設定ファイルを作る

以下の例ではnpmを使います。`init`を実行すると、ビルド専用の`decks/config.ts`、実行時の設定を書く`decks/index.ts`、サンプルのデッキが作られ、`.gitignore`に`.hono-decks/`が追加されます。既存のファイルは上書きされません。

<CodeBlock filename={"Terminal"} language={"bash"} code={"npm install hono-decks\nnpx hono-decks init"} copyLabel={"コピー"} copiedLabel={"コピーしました"} errorLabel={"コピーできませんでした"} />

| パッケージマネージャー | インストール | CLIの実行 |
| --- | --- | --- |
| npm | `npm install hono-decks` | `npx hono-decks <command>` |
| pnpm | `pnpm add hono-decks` | `pnpm exec hono-decks <command>` |
| Yarn | `yarn add hono-decks` | `yarn hono-decks <command>` |
| Bun | `bun add hono-decks` | `bunx hono-decks <command>` |

`<command>`には`init`や`compile`を指定します。以降の例も利用中のパッケージマネージャーに合わせて読み替えてください。

</section>

<section id={"deck"}>

## 最初のデッキを作ってコンパイルする

`decks/welcome/deck.mdx`を作成します。先頭のフロントマターはデッキ全体の情報、その次の`---`からが1枚目のスライドです。

<CodeBlock filename={"decks/welcome/deck.mdx"} language={"mdx"} code={"---\ntitle: Welcome\ndescription: My first hono-decks presentation\n---\n\n---\nlayout: cover\n---\n\n# Welcome\n\nThis deck is served from my Hono app.\n\n---\n\n## Next slide\n\n- Write slides in MDX\n- Serve them with Hono"} copyLabel={"コピー"} copiedLabel={"コピーしました"} errorLabel={"コピーできませんでした"} />

MDXをHono JSXモジュールへ変換します。成功すると`.hono-decks/`が作成されます。

<CodeBlock filename={"Terminal"} language={"bash"} code={"npx hono-decks compile"} copyLabel={"コピー"} copiedLabel={"コピーしました"} errorLabel={"コピーできませんでした"} />

**生成されるファイル**

<FileTree label={"Source files"}>
  <File name={"decks/config.ts"} />
  <Folder name={"decks"}>
    <File name={"index.ts"} />
    <Folder name={"welcome"}><File name={"deck.mdx"} /></Folder>
  </Folder>
</FileTree>

`decks/config.ts`はCLIだけが読むビルド設定です。アプリ側で管理する`decks/index.ts`と`deck.mdx`は編集してかまいません。一方、`.hono-decks/`はコンパイルのたびに上書きされるため、直接編集もコミットもしないでください。

</section>

<section id={"mount"}>

## 生成したルーターをHonoに登録する

生成したルーターを、既存のHonoアプリの`/decks`配下に登録します。

<CodeBlock filename={"TypeScript"} language={"typescript"} code={"// src/index.ts\nimport { Hono } from \"hono\"\nimport { decks } from \"../decks\"\n\nconst app = new Hono()\napp.route(decks.mountPath, decks.router())\n\nexport default app"} copyLabel={"コピー"} copiedLabel={"コピーしました"} errorLabel={"コピーできませんでした"} />

`decks.mountPath`は設定ファイルの値から生成されるため、コンパイル時と実行時で公開パスがずれません。別のパスにルーターを登録すると、分かりやすいエラーになります。

</section>

<section id={"scripts"}>

## 普段の開発コマンドで起動する

CLIのinitはpackage.jsonに `#decks` を登録し、既存のdev/build/typecheck/test/deployコマンドの前にコンパイルを追加します。内部キャッシュ `.hono-decks/` の編集やコミットは不要です。

cfのプロジェクトでは、`wrangler.config.ts` にコンパイルのフックを設定すると、`cf dev` がデッキの編集も検知します。Minimalサンプルを参照してください。既存のWranglerプロジェクトは [Cloudflareの移行手順](https://developers.cloudflare.com/cf/wrangler/migrate/) を先に実施します。Viteは `virtual:hono-decks` を使い、このキャッシュを書き出しません。

<CodeBlock filename={"package.json"} language={"jsonc"} code={"{\n  \"imports\": {\n    \"#decks\": \"./.hono-decks/decks.ts\"\n  },\n  \"scripts\": {\n    \"dev\": \"hono-decks compile && cf dev\",\n    \"build\": \"hono-decks compile && cf build\"\n  }\n}"} />

</section>

<section id={"verify"}>

## 汎用方式の表示を確認する

<CodeBlock filename={"Terminal"} language={"bash"} code={"npm run dev"} copyLabel={"コピー"} copiedLabel={"コピーしました"} errorLabel={"コピーできませんでした"} />

開発サーバーが表示したURLの`/decks/welcome`を開きます。Welcomeスライドが表示され、左右の操作または矢印キーで2枚目へ移動できれば導入は完了です。

<Callout title={"URLの例"}>

`http://localhost:3000/decks/welcome`。別のポートが表示された場合は、開発サーバーのURLを使ってください。

</Callout>

</section>
