# 導入

パッケージを追加し、最初のデッキをHonoアプリで表示するまでの手順です。

<section id={"prerequisites"}>

## Honoアプリを用意する

npm、pnpm、Yarn、Bunのいずれかと、起動できるHonoアプリが必要です。この手順が終わると、2枚のスライドを`/decks/welcome`で表示できます。

<Callout title={"コンパイルと配信は分かれています"}>

MDXの変換はローカルの開発・ビルド環境で行います。Honoアプリは生成済みモジュールを読み込むため、Cloudflare Workers上でファイルシステムへアクセスする必要はありません。

</Callout>

</section>

<section id={"framework-init"}>

## アプリに合った導入方法を選ぶ

既存のHono + ViteまたはHonoXアプリでは、`hono-decks`を追加して対応するコマンドを選びます。VoidではVoid用コマンドを使います。`--install`は不足している互換Markdown依存をアプリのパッケージマネージャーで追加します。未対応の設定や既存の統合がある場合はCLIの案内を確認してください。

```sh
npm install hono-decks
# いずれか1つを選ぶ
npx hono-decks init --framework hono
npx hono-decks init --framework honox
npx hono-decks init --framework void --install
npm run dev
```

いずれも既存のスクリプトを維持し、`virtual:hono-decks`を使用します。`dev`と`build`がメモリ内でデッキをコンパイルします。initが表示したサンプルのURL（通常は`/slides/welcome`）を開いてください。HonoとHonoXのサンプルはMDX、Voidは操作できるIslandを含むMarkdownです。対応バージョン、任意の依存関係、設定上の制約は[パッケージのREADME](https://github.com/ts-76/hono-decks/blob/main/packages/decks/README.ja.md)を参照してください。

以下は、手動統合やWrangler向けの**汎用CLI・ファイル生成方式**です。この方式の`init`は標準で`/decks`を使い、`compile`は生成ファイルをディスクに出力します。

</section>

<section id={"install"}>

## パッケージを追加し、設定ファイルを作る

以下の例ではnpmを使います。`init`を実行すると、CLIと実行時の共通設定`hono-decks.config.ts`と、生成コードをアプリにつなぐ`src/decks.ts`が作られます。既存のファイルは上書きされません。

<CodeBlock filename={"Terminal"} language={"bash"} code={"npm install hono-decks\nnpx hono-decks init"} copyLabel={"コピー"} copiedLabel={"コピーしました"} errorLabel={"コピーできませんでした"} />

| パッケージマネージャー | インストール | CLIの実行 |
| --- | --- | --- |
| npm | `npm install hono-decks` | `npx hono-decks <command>` |
| pnpm | `pnpm add hono-decks` | `pnpm exec hono-decks <command>` |
| Yarn | `yarn add hono-decks` | `yarn hono-decks <command>` |
| Bun | `bun add hono-decks` | `bunx hono-decks <command>` |

`<command>`には`init`や`compile`を指定します。以降の例も、利用中のパッケージマネージャーに合わせて読み替えてください。

</section>

<section id={"deck"}>

## 最初のデッキを作ってコンパイルする

`decks/welcome/deck.mdx`を作成します。先頭のフロントマターはデッキ全体の情報、その次の`---`からが1枚目のスライドです。

<CodeBlock filename={"decks/welcome/deck.mdx"} language={"mdx"} code={"---\ntitle: Welcome\ndescription: My first hono-decks presentation\n---\n\n---\nlayout: cover\n---\n\n# Welcome\n\nThis deck is served from my Hono app.\n\n---\n\n## Next slide\n\n- Write slides in MDX\n- Serve them with Hono"} copyLabel={"コピー"} copiedLabel={"コピーしました"} errorLabel={"コピーできませんでした"} />

MDXをHono JSXモジュールへ変換します。成功すると`src/generated/`が作成されます。

<CodeBlock filename={"Terminal"} language={"bash"} code={"npx hono-decks compile"} copyLabel={"コピー"} copiedLabel={"コピーしました"} errorLabel={"コピーできませんでした"} />

**生成されるファイル**

<FileTree label={"生成されるファイル"}>
  <File name={"hono-decks.config.ts"} />
  <Folder name={"decks"}>
    <Folder name={"welcome"}>
      <File name={"deck.mdx"} />
    </Folder>
  </Folder>
  <Folder name={"src"}>
    <File name={"decks.ts"} />
    <Folder name={"generated"}>
      <File name={"decks.ts"} highlighted />
    </Folder>
  </Folder>
</FileTree>

`hono-decks.config.ts`はCLIと実行時の共通設定です。アプリ側で管理する`src/decks.ts`と`deck.mdx`は編集してかまいません。一方、`src/generated/`はコンパイルのたびに上書きされるため、直接編集しないでください。

</section>

<section id={"mount"}>

## 生成したルーターをHonoに登録する

生成したルーターを、既存のHonoアプリの`/decks`配下に登録します。

<CodeBlock filename={"TypeScript"} language={"typescript"} code={"// src/index.ts\nimport { Hono } from \"hono\"\nimport { decks } from \"./decks\"\n\nconst app = new Hono()\napp.route(decks.mountPath, decks.router())\n\nexport default app"} copyLabel={"コピー"} copiedLabel={"コピーしました"} errorLabel={"コピーできませんでした"} />

`decks.mountPath`は設定ファイルの値から生成されるため、コンパイル時と実行時で公開パスがずれません。

</section>

<section id={"scripts"}>

## 普段の開発コマンドにコンパイルを組み込む

汎用ファイル生成方式でViteを使う場合は、既存のVite設定へプラグインを追加します。起動前にコンパイルし、デッキの変更を監視します。上記のフレームワーク別initではViteの設定は自動で追加され、仮想モジュールを使用します。Viteでは安全に差し替えられる内容の編集時、表示と対応するIslandの状態を維持します。クライアントコードの変更時や安全に差し替えられない場合は表示用iframeを再読み込みし、Islandの状態をリセットしてスライドとステップを復元します。viewerは開いたままです。

<CodeBlock filename={"vite.config.ts"} language={"typescript"} code={"import { honoDecks } from \"hono-decks/vite\"\nimport { defineConfig } from \"vite\"\n\nexport default defineConfig({\n  plugins: [honoDecks()],\n})"} copyLabel={"コピー"} copiedLabel={"コピーしました"} errorLabel={"コピーできませんでした"} />

<CodeBlock filename={"package.json"} language={"jsonc"} code={"{\n  \"scripts\": {\n    \"decks:compile\": \"hono-decks compile\",\n    \"dev\": \"vite\",\n    \"build\": \"vite build\"\n  }\n}"} copyLabel={"コピー"} copiedLabel={"コピーしました"} errorLabel={"コピーできませんでした"} />

Wranglerを直接使うCloudflare Workerでは、`wrangler.jsonc`のカスタムビルドへ登録します。`--live-reload`を付けると、普段の開発コマンドだけでデッキの変更監視とブラウザ更新まで行えます。

<CodeBlock filename={"wrangler.jsonc"} language={"jsonc"} code={"{\n  \"build\": {\n    \"command\": \"hono-decks compile\",\n    \"watch_dir\": [\"decks\"]\n  }\n}"} copyLabel={"コピー"} copiedLabel={"コピーしました"} errorLabel={"コピーできませんでした"} />

<CodeBlock filename={"package.json"} language={"jsonc"} code={"{\n  \"scripts\": {\n    \"dev\": \"wrangler dev --live-reload\"\n  }\n}"} copyLabel={"コピー"} copiedLabel={"コピーしました"} errorLabel={"コピーできませんでした"} />

</section>

<section id={"verify"}>

## ブラウザで表示を確認する

<CodeBlock filename={"Terminal"} language={"bash"} code={"npm run dev"} copyLabel={"コピー"} copiedLabel={"コピーしました"} errorLabel={"コピーできませんでした"} />

開発サーバーが表示したURLの`/decks/welcome`を開きます。Welcomeスライドが表示され、左右の操作または矢印キーで2枚目へ移動できれば導入は完了です。

<Callout title={"URLの例"}>

`http://localhost:3000/decks/welcome`。別のポートが表示された場合は、開発サーバーのURLを使ってください。

</Callout>

</section>
