# Configuration

Keep build settings in hono-decks.config.ts and runtime options in createDecks().

<section id={"files"}>

## Know which file owns each setting

`hono-decks init` creates `hono-decks.config.ts`, `src/decks.ts`, and a sample deck, and adds the generated directory to `.gitignore`. The config file is build-only: the CLI and the Vite plugin read it, and the Worker never imports it.

<DefinitionList items={[{term: <><code>{"hono-decks.config.ts"}</code></>, description: <>{"Build settings: the public mountPath, deck root, and output directory."}</>},
{term: <><code>{"src/decks.ts"}</code></>, description: <>{"Runtime options passed to createDecks(): viewer, presenter, export, source, and more."}</>},
{term: <><code>{"generated/"}</code></>, description: <>{"Compiler-owned modules. Rebuilt on every dev, build, and typecheck run; not committed."}</>},
{term: <><code>{"package.json"}</code></>, description: <>{"Runs the existing Vite or Wrangler development command."}</>}]} />

<CodeBlock filename={"hono-decks.config.ts"} language={"typescript"} code={"// hono-decks.config.ts\nimport { defineDecksConfig } from \"hono-decks\"\n\nexport default defineDecksConfig({\n  mountPath: \"/decks\",\n  build: { root: \"decks\", outDir: \"src/generated\" },\n})"} copyLabel={"Copy code"} copiedLabel={"Copied"} errorLabel={"Copy failed"} />

With Vite (`init --framework hono`, `honox`, or `void`), modules stay in memory and `src/decks.ts` imports `createDecks` from `virtual:hono-decks`. `build.outDir` is not needed.

```ts
/// <reference types="hono-decks/vite-env" />
import { createDecks } from "virtual:hono-decks"

export const decks = createDecks()
```

<Callout title={"Two files, two jobs"}>

The compiler reads `build` and bakes `mountPath` into the generated module. Everything that runs per request goes to `createDecks()`.

</Callout>

</section>

<section id={"compile"}>

## Connect the compiler to the dev lifecycle

Add `honoDecks()` to Vite, or register `hono-decks compile` as a Wrangler custom build. Either way, your existing `dev` command compiles decks; no separate script is needed.

<CodeBlock filename={"vite.config.ts"} language={"typescript"} code={"import { honoDecks } from \"hono-decks/vite\"\nimport { defineConfig } from \"vite\"\n\nexport default defineConfig({\n  plugins: [honoDecks()],\n})"} copyLabel={"Copy code"} copiedLabel={"Copied"} errorLabel={"Copy failed"} />

<CodeBlock filename={"wrangler.jsonc"} language={"jsonc"} code={"{\n  \"build\": {\n    \"command\": \"hono-decks compile\",\n    \"watch_dir\": [\"decks\"]\n  }\n}"} copyLabel={"Copy code"} copiedLabel={"Copied"} errorLabel={"Copy failed"} />

<section id={"runtime"}>

## Configure values that change per request

Pass runtime options to `createDecks()`. Its type parameter type-checks Hono Bindings and Variables in every resolver. When `dev` is omitted, hono-decks reads the `NODE_ENV` set by Vite and Wrangler. With their standard settings, `vite` and `wrangler dev` use development mode, while production builds and `wrangler deploy` use production mode. An explicit boolean or resolver takes precedence. If the environment cannot be detected, hono-decks defaults safely to production mode.

<CodeBlock filename={"TypeScript"} language={"typescript"} code={"// src/decks.ts\nimport { createDecks } from \"./generated/decks\"\n\ntype AppEnv = {\n  Bindings: {\n    PRESENTER_ENABLED?: string\n  }\n  Variables: {\n    language: string\n  }\n}\n\nexport const decks = createDecks<AppEnv>({\n  document: {\n    lang: ({ c }) => c.get(\"language\"),\n  },\n  presenter: {\n    enabled: ({ c, dev }) => dev || c.env.PRESENTER_ENABLED === \"true\",\n  },\n})"} copyLabel={"Copy code"} copiedLabel={"Copied"} errorLabel={"Copy failed"} />

The `c.get("language")` example assumes Hono's `languageDetector()` is registered first; see [document policy and security](/docs/security?lang=en#language). For a single-language app, use a fixed value such as `lang: "en"`.

</section>

<section id={"facade"}>

## Make precedence explicit

Generated defaults, app config from `createDecks()`, and `decks.router(overrides)` are applied in order. One merge rule applies everywhere: objects merge recursively, arrays concatenate, and any other value — including `false` and functions — replaces the earlier one.

<CodeBlock filename={"TypeScript"} language={"typescript"} code={"// src/index.ts\napp.route(\n  decks.mountPath,\n  decks.router({ viewer: { controls: { hidden: [\"print\"] } } }),\n)"} copyLabel={"Copy code"} copiedLabel={"Copied"} errorLabel={"Copy failed"} />

<Callout title={"One mount path"}>

Write `mountPath` once in the config and use `decks.mountPath` at runtime. Mounting the router anywhere else fails with an explicit error.

</Callout>
