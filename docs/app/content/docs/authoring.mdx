# Author an MDX deck

Use the Markdown, MDX, and deck-specific syntax supported by the compiler.

<section id={"structure"}>

## Keep each deck in its own directory

Use `decks/<slug>/deck.mdx`. The directory name becomes the URL slug, so `decks/launch/deck.mdx` appears at `/decks/launch`.

The opening `---` block contains deck metadata. Later separators start new slides, so a bare `---` cannot be used as a thematic break inside a slide.

<section id={"markdown-adapter"}>

## Use Markdown with an adapter

MDX is the default for Hono and HonoX. To use `deck.md`, configure a Markdown adapter and install its compiler dependencies; Void init configures its adapter automatically. The [Markdown adapter guide](https://github.com/ts-76/hono-decks#markdown-adapters) covers the Hono Markdown bridge and package requirements.

In Hono Markdown, islands use relative default TSX/JSX imports in a `<script>` block, with `island: "load"`, `"visible"`, `"idle"`, or `"media:(query)"`. Island tags accept literal string and boolean props. Arbitrary script code, JSX expressions, and children inside island tags are unsupported. MDX continues to support its own component registry and expressions.

~~~md
<script>
import Counter from "./Counter.tsx" with { island: "load" };
</script>
---
title: Interactive slide
---
# Demo

<Counter label="Count" initial="2" />
~~~

<section id={"fire"}>

## Reveal content one step at a time with fire

Add `fire` to a component to reveal it in source order. Use `:::fire` for Markdown and `:::fire{each="item"}` for list items. Use `<Fire>` to group multiple JSX elements into one step. The compiler removes `fire` before rendering the component.

<CodeBlock filename={"MDX"} language={"mdx"} code={"<Card fire />\n\n<Chart fire=\"scale\" at=\"2\" />\n\n:::fire{at=\"+2\"}\nMarkdown block\n:::\n\n:::fire{each=\"item\" depth=\"2\" every=\"2\"}\n- Parent one\n  - Child one\n- Parent two\n  - Child two\n:::\n\n<Fire effect=\"fade-up\">\n  <Heading />\n  <Description />\n</Fire>"} copyLabel={"Copy code"} copiedLabel={"Copied"} errorLabel={"Copy failed"} />

The staged-reveal model and the `at`, `depth`, and `every` options draw in part on Slidev's [`v-click` and `v-clicks`](https://sli.dev/guide/animations). The syntax and implementation are specific to hono-decks; compatibility with Slidev is not guaranteed. `at="2"` sets an absolute position, while `at="+2"` advances two steps from the current position. For lists, `depth` selects the nested levels and `every` sets how many items appear per step. Both default to `1`.

### Choose an effect

Use `fire="scale"` on a component and `effect="scale"` with `:::fire`. Built-ins are `none`, `fade`, `fade-up`, and `scale`. Define custom effects in `theme.css`.

<CodeBlock filename={"MDX"} language={"mdx"} code={"<Chart fire=\"blur-in\" />\n\n:::fire{effect=\"blur-in\"}\nMarkdown block\n:::"} copyLabel={"Copy code"} copiedLabel={"Copied"} errorLabel={"Copy failed"} />

<CodeBlock filename={"theme.css"} language={"css"} code={"[data-fire-effect=\"blur-in\"] {\n  --fire-transform: scale(.98);\n  --fire-filter: blur(12px);\n  --fire-duration: .32s;\n  --fire-easing: ease-out;\n}"} copyLabel={"Copy code"} copiedLabel={"Copied"} errorLabel={"Copy failed"} />

<section id={"notes"}>

## Add notes for the presenter

Text under `notes: |` and MDX comments are combined into presenter notes and omitted from the slide. Every MDX comment is treated as a note, even if you intended it only as a source-code comment.

<CodeBlock filename={"MDX"} language={"mdx"} code={"---\nnotes: |\n  Explain why generation runs before deployment.\n---\n\n# Build once, serve anywhere\n\n{/* Mention the generated module boundary. */}"} copyLabel={"Copy code"} copiedLabel={"Copied"} errorLabel={"Copy failed"} />

### Use an island only for browser interaction

Use `components/client/index.tsx` only for components that need clicks or local state. The compiler generates and serves the client entry, so ordinary applications do not add a separate asset route.

## Reference assets and embeds explicitly

Reference images under `decks/launch/assets/` with paths relative to `deck.mdx`. Explicit directives are available for `youtube`, `x`, `card`, `embed`, and `iframe`.

<CodeBlock filename={"MDX"} language={"mdx"} code={"![Architecture](./assets/runtime-boundary.svg)\n\n@[youtube](https://www.youtube.com/watch?v=VIDEO_ID)\n@[x](https://x.com/honojs/status/POST_ID)\n@[card](https://hono.dev/docs/)\n@[embed](https://example.com/demo)\n@[iframe](https://example.com/demo)"} copyLabel={"Copy code"} copiedLabel={"Copied"} errorLabel={"Copy failed"} />

A bare URL on its own line becomes a normal link. Configure [CSP and allowed origins](/docs/security?lang=en) before publishing external iframes. To serve assets from R2, use `withR2Assets()` without changing MDX paths.

<section id={"verify"}>

## Preview changes with the dev command

<CodeBlock filename={"Terminal"} language={"bash"} code={"npm run dev"} copyLabel={"Copy code"} copiedLabel={"Copied"} errorLabel={"Copy failed"} />

While the configured Vite or Wrangler `dev` command is running, saved deck sources are recompiled automatically. With Vite, supported content edits preserve the presentation and island state; client code edits or unsafe updates reload the presentation iframe and reset island state while retaining the viewer and slide/step. Direct Wrangler live reload follows Wrangler behavior. Use `npx hono-decks compile` when checking the CLI/file compiler separately. Compile errors identify the source file and slide number.

After the deck renders, continue to [routes and UI](/docs/routing?lang=en) for public surfaces or [configuration](/docs/configuration?lang=en) for bindings and R2.

</section>
