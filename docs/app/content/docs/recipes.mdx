# OGP images and file export

Add build-time OGP image generation with Satori and PDF or PNG export with Cloudflare Browser Run.

<section id={"ogp"}>

## Save OGP images at build time with Satori

Generate an SVG with Satori and a 1200×630 PNG with resvg from the manifest returned by `compileDecks()`, without Browser Rendering. Keep image generation in a Node build script so neither the Worker runtime nor hono-decks core gains these dependencies.

<CodeBlock filename={"src/decks.ts"} language={"typescript"} code={"// src/decks.ts\nexport const decks = createDecks({\n  viewer: { openGraph: true },\n})"} copyLabel={"Copy code"} copiedLabel={"Copied"} errorLabel={"Copy failed"} />

Enabling `viewer.openGraph` emits absolute Open Graph and Twitter Card tags from `decks.paths(slug).ogImage`, which defaults to `/decks/:slug/og.png`. Save the PNG under Wrangler Static Assets.

To let X posts play the deck inline, set `viewer.openGraph.twitterPlayer` and enable `embed`. The Player Card frames `/:slug/embed`, and hono-decks adds X's origins to its `frame-ancestors`. X no longer documents Player Cards. In a [public test from October 2026](https://thehouse.game/updates/2026-10-22-interactive-x-embeds), web posts played inline without approval, the mobile apps opened the embed in a web view, and the player did not work in X Articles, so keep generating it.

```ts
export const decks = createDecks({
  embed: {},
  viewer: { openGraph: { twitterPlayer: true } },
})
```

<Callout title={"Keep fonts in the build input"}>

Satori accepts TTF, OTF, and WOFF, but not WOFF2. Bundle a font that covers every rendered language and add its directory to `build.watch_dir` in `wrangler.jsonc`.

</Callout>

[Open the complete Satori + resvg recipe →](https://github.com/ts-76/hono-decks/tree/main/examples/ogp)

`build.ogpCacheFile` caches LinkCard metadata inside slides; it is unrelated to this viewer share image.

</section>

## Export PDF and PNG with Browser Run

Use Cloudflare Browser Run Quick Actions through a browser binding to return the deck's `print` page as PDF or PNG. `hono-decks` calls `quickAction("pdf")` or `quickAction("screenshot")`, so this flow needs neither Puppeteer, Playwright, nor a Browser Run API token.

<CodeBlock filename={"wrangler.jsonc"} language={"jsonc"} code={"{\n  \"compatibility_date\": \"2026-07-15\",\n  \"browser\": {\n    \"binding\": \"BROWSER\",\n    \"remote\": true\n  }\n}"} copyLabel={"Copy code"} copiedLabel={"Copied"} errorLabel={"Copy failed"} />

<Callout title={"Use a remote binding during local development"}>

`quickAction()` requires a compatibility date of `2026-03-24` or later. Local mode does not support it yet, so set `remote: true` on the binding or start with `wrangler dev --remote`.

</Callout>

The next example assumes an earlier session or Cloudflare Access validation middleware has set `deckExportAllowed`.

<CodeBlock filename={"src/decks.ts"} language={"typescript"} code={"// src/decks.ts\nimport type { DeckBrowserRunBinding } from \"hono-decks\"\nimport { createDecks } from \"#decks\"\n\ntype AppEnv = {\n  Bindings: {\n    BROWSER: DeckBrowserRunBinding\n  }\n  Variables: {\n    deckExportAllowed: boolean\n  }\n}\n\nexport const decks = createDecks<AppEnv>({\n  export: {\n    browser: ({ c }) => c.env.BROWSER,\n    authorize: ({ c }) => c.get(\"deckExportAllowed\") === true,\n    pdf: true,\n    png: true,\n  },\n})"} copyLabel={"Copy code"} copiedLabel={"Copied"} errorLabel={"Copy failed"} />

| Route / API | Purpose |
| --- | --- |
| `/:slug/print` | All-slide document used as Browser Run input |
| `/:slug/export.pdf` | Download the print document as PDF |
| `/:slug/export.png` | Download a full-page PNG of the print document |

After `authorize` succeeds, the export request sends the public `print` URL to the binding and returns its file as an attachment. Viewer export controls are shown only on requests that pass the same authorization.

<Callout title={"authorize only controls PDF and PNG export"}>

`authorize` applies to `/:slug/export.pdf`, `/:slug/export.png`, and their viewer controls. It does not protect the viewer, presentation, presenter, or `print` routes. `authorize: () => true` lets anyone export a file. Omitting it has the same public behavior, so an explicit setting is recommended. To restrict exports, return the result of existing session or Access validation.

</Callout>

Store bearer tokens as Wrangler secrets rather than plain `vars` values.

[Read the Cloudflare Browser Run Quick Actions docs →](https://developers.cloudflare.com/browser-run/quick-actions/)

[Open the example with Browser Run configured →](https://github.com/ts-76/hono-decks/tree/main/examples/basic)

## Cross-device presentation control

Export `DeckRemoteRoom` from your Worker entry and add a binding and migration. This class must be reachable only through the router; do not expose its trusted internal headers directly.

```ts
export { DeckRemoteRoom } from "hono-decks/remote";
```

```jsonc
{
  "durable_objects": { "bindings": [{ "name": "ROOMS", "class_name": "DeckRemoteRoom" }] },
  "migrations": [{ "tag": "v1", "new_sqlite_classes": ["DeckRemoteRoom"] }]
}
```

For example, store a random presenter token with `wrangler secret put PRESENTER_TOKEN`. After authentication, your app may issue it as an HttpOnly, Secure, SameSite=Strict cookie named `presenter`; never put the secret in source or `vars`. The following assumes the app has already issued that cookie over HTTPS. Protect presenter and other note-bearing routes separately.

```ts
import { getCookie } from "hono/cookie";
import { createDecks } from "#decks";

type AppEnv = { Bindings: { ROOMS: DurableObjectNamespace; PRESENTER_TOKEN: string } };
const presenterAllowed = (c: import("hono").Context<AppEnv>) => {
  const actual = new TextEncoder().encode(getCookie(c, "presenter") ?? "");
  const expected = new TextEncoder().encode(c.env.PRESENTER_TOKEN ?? "");
  return expected.length > 0 && actual.length === expected.length && crypto.subtle.timingSafeEqual(actual, expected);
};
export const decks = createDecks<AppEnv>({
  presenter: { enabled: ({ c }) => presenterAllowed(c) },
  remote: {
    namespace: ({ c }) => c.env.ROOMS,
    authorize: ({ c, role }) => role === "follower" || presenterAllowed(c),
  },
});
```

Followers may see live positions in this public example. Grant presenter only to trusted users: presenters can control the room, and the remote page contains notes. The socket sends no notes, validates messages, caps them at 1 KB and limits each connection. `remote.authorize` does not secure other routes such as print. Use HTTPS and a strict CSP with `connect-src` permitting same-origin WebSockets (`'self'` or explicit `wss:`/`ws:` as required by browsers). Keep the presenter page open to execute relative commands. The local-only `fixtures/remote-worker` is for testing and deliberately allows everyone.
